1. Зачем это: баги, которые растут из непонимания фундамента #

Четыре строчки, четыре классических бага. Ни один не является «редким краевым случаем» — с каждым вы уже сталкивались, а если нет — столкнётесь на первом собеседовании.

// Баг 1: значение "0" истинно? А пустая строка?
function describe(qty) {
  if (qty) return `В наличии: ${qty}`;
  return 'Нет в наличии';
}
describe(0);              // "Нет в наличии" — а если 0 это ВАЛИДНОЕ количество (закончился товар после продажи)?

// Баг 2: замыкание в цикле
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// Ожидание: 0 1 2       Реальность: 3 3 3

// Баг 3: this внутри колбэка
const cart = {
  items: ['bolt', 'nut'],
  printItems() {
    this.items.forEach(function (item) {
      console.log(this.prefix, item);   // TypeError или undefined — this здесь не cart!
    });
  },
  prefix: '→',
};
cart.printItems();

// Баг 4: сравнение объектов
const a = { qty: 5 };
const b = { qty: 5 };
console.log(a === b);      // false — а почему падает тест "ожидал {qty:5}, получил {qty:5}"?
БагЧто происходит на самом делеГде разбираем
1. Falsy-ловушка0, '', NaN, null, undefined — все ложны; if (qty) не отличает «нет данных» от «данные — ноль»раздел 3
2. var в циклеvar не создаёт новую область видимости на каждой итерации — все три колбэка делят ОДНУ переменную i, которая к моменту вызова уже 3раздел 2
3. Потеря thisобычная функция в колбэке получает свой this (в строгом режиме — undefined), не тот, что у cartраздел 5
4. Сравнение по ссылкеобъекты и массивы сравниваются по идентичности, не по содержимому — {} никогда не равен другому {}, даже с теми же полямираздел 4

Общий знаменатель: в JavaScript почти всё — договорённость, а не защита. Язык не мешает вам сравнить объекты через === (просто это не то сравнение, которое вы хотели), не мешает объявить var в цикле (просто область видимости не та, что вы думали). Фреймворки типа Vue берут часть этих договорённостей на себя и прячут — эта лаба про то, что именно они прячут и почему.

2.2 Hoisting — «поднятие» объявлений

Перед выполнением JS-движок делает проход по коду и регистрирует все объявления функций и переменных в текущей области видимости — до того, как выполнится первая строка. Отсюда:

console.log(a);        // undefined, НЕ ReferenceError — var подняли и инициализировали
var a = 5;

console.log(sayHi());  // "Hi!" — работает: объявление функции целиком поднимается вместе с телом
function sayHi() { return 'Hi!'; }

console.log(b);        // ReferenceError: Cannot access 'b' before initialization
let b = 10;

2.3 Temporal Dead Zone (TDZ)

«Мёртвая зона» — промежуток между началом блока и строкой объявления let/const, где переменная уже зарегистрирована движком (поэтому не undefined, как у var), но обратиться к ней нельзя. TDZ — не баг, а страховка: она превращает «использование переменной раньше объявления» из тихой ошибки (undefined, которая всплывёт бог знает где) в громкую (ReferenceError сразу на месте).

2.4 Function scope vs block scope

function demo() {
  if (true) {
    var fnScoped = 'я снаружи блока';
    let blockScoped = 'я только внутри блока';
  }
  console.log(fnScoped);     // работает — var видна во всей функции
  console.log(blockScoped);  // ReferenceError — let умер вместе с блоком if
}

2.5 Замыкание в цикле — механика бага из раздела 1

// var: одна переменная на весь цикл — все замыкания видят её финальное значение
for (var i = 0; i < 3; i++) { setTimeout(() => console.log('var:', i), 0); }

// let: НОВАЯ переменная i на КАЖДОЙ итерации — движок буквально создаёт новое связывание в блоке цикла
for (let j = 0; j < 3; j++) { setTimeout(() => console.log('let:', j), 0); }

// var: 3 3 3      let: 0 1 2
🔬 Под капотом: почему у let своя переменная на каждой итерации, а не одна

Спецификация ECMAScript явно описывает for (let ...) как создание нового лексического окружения на каждой итерации, куда копируется текущее значение счётчика перед выполнением тела. Это не «магия» — это буквально то, что раньше писали руками через IIFE (immediately invoked function expression) до появления let: for (var i = 0; i < 3; i++) { (function (i) { setTimeout(() => console.log(i), 0); })(i); }. let в цикле — синтаксический сахар именно над этим паттерном.

Область видимости — не абстрактная тема из учебника, а то, что определяет, «какую переменную вообще видит эта строка кода». В сессии 1 вы воспроизведёте баг из раздела 1 и почините его тремя разными способами.

3.2 == vs === — что на самом деле делает нестрогое сравнение

== не «сравнивает нестрого» — оно выполняет приведение типов по конкретному алгоритму (Abstract Equality Comparison) и только потом сравнивает. Выучить весь алгоритм не нужно — нужно запомнить пять результатов, которые ломают интуицию:

0 == ''          // true   — строка приводится к числу: Number('') === 0
0 == '0'         // true   — Number('0') === 0
0 == false       // true   — false приводится к 0
'' == false      // true   — оба приводятся к 0
null == undefined // true  — специальное правило: равны ДРУГ ДРУГУ и больше никому
null == 0         // false — а вот это уже НЕ работает, хотя логика "оба ложны" подсказывает обратное
NaN == NaN        // false — NaN не равен даже самому себе (единственное такое значение)
[] == false       // true   — [] → '' → 0; false → 0
[] == ![]         // true   — классика собеседований: ![] это false, дальше как в строке выше

Правило лабы: всегда ===, кроме одного места — x == null как компактная проверка «null или undefined» (единственный оправданный случай нестрогого сравнения, потому что использует именно то специальное правило из таблицы).

3.3 Truthy / falsy

Ложны ровно восемь значений: false, 0, -0, 0n, '', null, undefined, NaN. Все остальные значения истинны — включая '0' (строка с нулём), [] (пустой массив), {} (пустой объект). Это и есть баг 1 из раздела 1: if (qty) ложно не только для «нет данных», но и для «данных 0» — оба падают в одну ветку.

3.4 NaN — Not a Number, но typeof "number"

typeof NaN            // "number" — NaN это специальное числовое значение, а не отдельный тип
NaN === NaN            // false
Number.isNaN(NaN)      // true  — надёжная проверка
isNaN('hello')         // true  — ГЛОБАЛЬНАЯ isNaN сначала приводит к числу: Number('hello') это NaN → true. Ловушка!
Number.isNaN('hello')  // false — Number.isNaN НЕ приводит типы: строка это не NaN, это строка

🔬 Под капотом: object → primitive: как объект превращается в строку или число

Когда объект участвует в операции, требующей примитив (String(obj), obj + '', obj == 'что-то'), движок вызывает внутренний алгоритм ToPrimitive: сначала пробует Symbol.toPrimitive (если определён), потом valueOf(), потом toString(). Для массива toString() — это join(','), отсюда String([1,2]) === '1,2'. Для обычного объекта toString() даёт '[object Object]'. Определить своё поведение: const item = { valueOf() { return this.price; } }; item + 10 сработает как число.

// Spread: РАЗворачивает — используется там, где ожидается несколько элементов
const a = [1, 2], b = [3, 4];

🔬 Под капотом: поверхностное копирование: где spread не спасает
const original = { status: 'open', meta: { assignee: 'anna' } };

🔬 Под капотом: reduce как швейцарский нож: почему им можно выразить map и filter

reduce — самый общий метод: arr.map(fn) эквивалентен arr.reduce((acc, x) => [...acc, fn(x)], []), а filter — arr.reduce((acc, x) => cond(x) ? [...acc, x] : acc, []). Обратное неверно — через map/filter нельзя построить произвольную группировку в объект. Практическое правило: если результат — массив той же формы, что вход, берите map/filter (они читаются понятнее и не мутируют случайно); если результат — объект, число, или структура другой формы — reduce.

5. this, call/apply/bind, стрелочные функции #

Главное правило: this определяется тем, как функцию вызвали, а не тем, где она объявлена — за одним исключением (стрелочные функции). Четыре способа вызова — четыре разных this:

function show() { console.log(this); }

show();                          // вызов "просто так" → this === undefined (в strict mode / модулях) или globalThis
const obj = { show };
obj.show();                      // вызов КАК МЕТОД → this === obj
show.call({ x: 1 });             // явно задан → this === { x: 1 }
new show();                       // вызов КАК КОНСТРУКТОР → this === новый пустой объект

6. Замыкания и практические паттерны #

Замыкание — функция, которая «помнит» переменные из области, где была создана, даже после того как эта область формально завершила выполнение. Это не экзотика — это то, как работает любой колбэк, любой обработчик события, любой модуль.

function makeCounter() {
  let count = 0;                       // приватная переменная — недоступна снаружи никак, кроме как через возвращённые функции
  return {
    increment: () => ++count,
    reset: () => { count = 0; },
    get value() { return count; },
  };
}
const counter = makeCounter();
counter.increment(); counter.increment();
console.log(counter.value);            // 2
console.log(counter.count);            // undefined — снаружи переменной count не существует вообще

6.1 Приватность до #private: module pattern

До появления приватных полей класса (раздел 7) замыкание было ЕДИНСТВЕННЫМ способом сделать что-то по-настоящему недоступным снаружи — не «соглашением об именовании» (_private), а физической невозможностью достучаться.

6.2 Каррирование

// Обычная функция трёх аргументов
function discount(percent, tax, price) { return price * (1 - percent) * (1 + tax); }

// Каррированная версия — можно "заполнять" аргументы по одному, получая функцию каждый раз
const curriedDiscount = (percent) => (tax) => (price) => price * (1 - percent) * (1 + tax);

const withStandardDiscount = curriedDiscount(0.1);      // "зафиксировали" процент скидки — получили функцию от (tax)
const withStandardTax = withStandardDiscount(0.2);       // зафиксировали налог — получили функцию от (price)
withStandardTax(100);                                     // 90 — можно переиспользовать withStandardDiscount для разных price

6.3 Мемоизация

function memoize(fn) {
  const cache = new Map();                     // замыкание хранит кэш между вызовами возвращённой функции
  return (...args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) { console.log('из кэша'); return cache.get(key); }
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

function slowSquare(n) { for (let i = 0; i < 1e8; i++); return n * n; }   // искусственно медленная
const fastSquare = memoize(slowSquare);
fastSquare(5);      // считает медленно
fastSquare(5);      // "из кэша" — мгновенно
🔬 Под капотом: утечки памяти через замыкания: когда "помнить" — плохо

Замыкание держит ссылку на всю область видимости, где было создано, — не только на переменные, которые реально использует. Если в большой функции объявлен огромный массив, а возвращённое замыкание использует лишь одну маленькую переменную из той же области, движок (в некоторых реализациях) всё равно не может освободить память под массив, пока живо замыкание. Практический вывод: DOM-обработчики событий, которые держат замыкание на объект с большими данными и никогда не снимаются (removeEventListener) — частый источник утечек в SPA; это будет видно в разделе про DOM.

7. Прототипы и class #

В JavaScript нет «классов» на уровне движка — есть прототипное наследование: каждый объект может ссылаться на другой объект (свой прототип) и искать в нём поля, которых нет у него самого. class — синтаксис поверх этого механизма, появившийся в ES6 для читаемости.

7.1 Цепочка прототипов вручную

const animalProto = {
  speak() { return `${this.name} издаёт звук`; },
};
const dog = Object.create(animalProto);      // dog.__proto__ === animalProto, БЕЗ class вообще
dog.name = 'Рекс';
dog.speak();                                  // "Рекс издаёт звук" — метод найден не у dog, а у его прототипа

console.log(dog.hasOwnProperty('speak'));    // false — speak НЕ собственное свойство dog
console.log('speak' in dog);                  // true — но доступно через цепочку прототипов
console.log(Object.getPrototypeOf(dog) === animalProto);   // true

7.2 class — тот же механизм, другой синтаксис

class Animal {
  constructor(name) { this.name = name; }        // будет вызван при new Animal(...)
  speak() { return `${this.name} издаёт звук`; }  // попадёт в Animal.prototype, НЕ в каждый экземпляр
}
class Dog extends Animal {
  speak() { return `${super.speak()} (гав!)`; }   // super обращается к методу родителя ЯВНО
}
const rex = new Dog('Рекс');
rex.speak();                                        // "Рекс издаёт звук (гав!)"

// Доказательство, что class — сахар:
console.log(typeof Animal);                          // "function" — класс это функция!
console.log(rex.speak === Dog.prototype.speak);       // true — метод лежит в prototype, как и в примере с Object.create
console.log(Object.getPrototypeOf(Dog.prototype) === Animal.prototype);   // true — цепочка прототипов та же самая

7.3 Приватные поля, статика, геттеры/сеттеры

class BankAccount {
  #balance = 0;                                   // #field — приватное поле, недоступно ДАЖЕ через obj.#balance снаружи класса
  static #accountsOpened = 0;                      // статическое приватное поле — общее для всех экземпляров

  constructor(owner) {
    this.owner = owner;
    BankAccount.#accountsOpened++;
  }

  deposit(amount) {
    if (amount <= 0) throw new RangeError('сумма должна быть положительной');
    this.#balance += amount;
    return this;                                   // return this — включает цепочку вызовов (chaining)
  }

  get balance() { return this.#balance; }           // геттер — читается КАК свойство: account.balance, без скобок
  set balance(value) { throw new Error('баланс нельзя присвоить напрямую, используйте deposit/withdraw'); }

  static get accountsOpened() { return BankAccount.#accountsOpened; }   // статический геттер
}

const acc = new BankAccount('Анна');
acc.deposit(100).deposit(50);                        // chaining благодаря return this
console.log(acc.balance);                             // 150
console.log(acc.#balance);                            // SyntaxError НА ЭТАПЕ ПАРСИНГА — не рантайм-ошибка, а именно синтаксис
acc.balance = 999;                                     // Error: баланс нельзя присвоить напрямую
console.log(BankAccount.accountsOpened);               // 1
🔬 Под капотом: #private vs _convention: в чём разница на уровне движка

this._balance (подчёркивание) — договорённость между разработчиками, ничем не защищённая: acc._balance = 999 сработает молча. #balance — часть синтаксиса языка: движок в буквальном смысле не даёт скомпилировать код, который обращается к #balance вне тела класса — это SyntaxError, а не undefined и не исключение в рантайме. Это ровно тот уровень инкапсуляции, которого не хватало в JS до ES2022 и который был нужен для честной реализации Encapsulation из ООП-принципов.

8.3 WeakMap / WeakSet — не мешают сборщику мусора

Обычный Map держит «сильную» ссылку на ключ-объект: пока запись в Map существует, объект-ключ не может быть удалён сборщиком мусора, даже если больше нигде не используется — потенциальная утечка памяти (см. «под капотом» раздела 6). WeakMap держит «слабую» ссылку: если объект-ключ больше нигде не используется, сборщик мусора имеет право удалить и его, и запись в WeakMap — автоматически, без вашего участия. Плата: WeakMap не перечисляем (нет .size, нет for...of) — вы не можете «просто посмотреть, что там есть», только обратиться по конкретному ключу. Типичное применение — приватные данные, привязанные к DOM-элементу, которые должны исчезнуть вместе с ним.

9. Event Loop: call stack, microtask, macrotask #

JavaScript однопоточный: одновременно выполняется только один кусок кода. Асинхронность — не про параллелизм, а про порядок, в котором отложенный код встаёт в очередь на выполнение. Это самая частая тема на собеседованиях именно потому, что интуиция здесь обманывает почти всегда.

┌─────────────────────────────────────────────────────────────────┐
│  Call Stack (стек вызовов)                                       │  ← выполняется ПРЯМО СЕЙЧАС, синхронно
│  функция вызывает функцию — растёт вниз, возвращается — падает   │
└─────────────────────────────────────────────────────────────────┘
              │  стек опустел → движок проверяет очереди
              ▼
┌──────────────────────────────┐   ┌──────────────────────────────┐
│  Microtask Queue               │   │  Macrotask Queue (Task Queue) │
│  Promise.then/catch/finally,   │   │  setTimeout, setInterval,      │
│  queueMicrotask, MutationObs.  │   │  I/O, событие DOM (click...)   │
│  ВЫСОКИЙ приоритет:             │   │  НИЗКИЙ приоритет:              │
│  очередь опустошается          │   │  ОДНА задача за раз, потом      │
│  ЦЕЛИКОМ перед каждым          │   │  снова проверяется вся          │
│  macrotask                     │   │  microtask queue                │
└──────────────────────────────┘   └──────────────────────────────┘
console.log('1: синхронный код');

setTimeout(() => console.log('2: macrotask (setTimeout)'), 0);

Promise.resolve().then(() => console.log('3: microtask (promise)'));

console.log('4: синхронный код');

// Порядок вывода: 1, 4, 3, 2
// НЕ 1, 2, 3, 4 (как думает интуиция про "0 миллисекунд")
// НЕ 1, 4, 2, 3 (microtask ВСЕГДА раньше macrotask, даже при setTimeout(fn, 0))

Разбор по шагам: (1) синхронный код выполняется весь целиком, пока стек не опустеет — console.log('1') и console.log('4') выполнятся прежде, чем движок вообще посмотрит на очереди. (2) setTimeout(fn, 0) не означает «выполнить через 0 миллисекунд» — это означает «положить в macrotask-очередь как можно скорее», но она обрабатывается только после того, как полностью опустеет microtask-очередь. (3) Поэтому Promise.then (microtask) всегда обгоняет даже нулевой setTimeout (macrotask).

// Более сложный пример — часто встречается на собеседованиях именно в такой форме
console.log('A');
setTimeout(() => console.log('B'), 0);
Promise.resolve().then(() => {
  console.log('C');
  Promise.resolve().then(() => console.log('D'));   // microtask, поставленный ВНУТРИ microtask
});
Promise.resolve().then(() => console.log('E'));
console.log('F');
// Ответ: A, F, C, E, D, B
// Почему D раньше B: очередь microtask опустошается ПОЛНОСТЬЮ, включая то, что добавляется по ходу её же обработки,
// и только потом движок переходит к следующему macrotask
🔬 Под капотом: setTimeout(fn, 0) в браузере: ещё не сразу

В браузерах (спецификация HTML, не ECMAScript) минимальная задержка setTimeout на верхнем уровне вложенности — не 0, а как минимум ~4мс (защита от блокировки основного потока частыми таймерами), плюс для фоновых вкладок задержка может быть увеличена браузером ради экономии батареи. В Node.js похожий, но не идентичный набор фаз event loop (там ещё есть process.nextTick, который приоритетнее даже обычных Promise-microtask, и отдельные фазы для I/O). Для практики в этой лабе достаточно двухуровневой модели «microtask всегда раньше macrotask» — она верна и в браузере, и в Node.

10.2 Promise — объект-обещание будущего значения

Три состояния: pending (ожидание) → fulfilled (успех, есть значение) или rejected (провал, есть причина). Переход необратим: однажды выполненный или отклонённый Promise не может сменить состояние.

function getTicketAsync(id) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (id > 0) resolve({ id, title: 'Задача' });
      else reject(new Error('некорректный id'));
    }, 100);
  });
}

getTicketAsync(1)
  .then(ticket => getAssigneeAsync(ticket.assigneeId))   // .then возвращает НОВЫЙ Promise — можно продолжать цепочку
  .then(user => getWorkspaceAsync(user.workspaceId))
  .then(workspace => console.log(workspace.name))
  .catch(error => console.error('где-то в цепочке:', error.message))    // ОДИН catch на всю цепочку
  .finally(() => console.log('выполнено в любом случае'));

10.3 async/await — синтаксический сахар над Promise

async function loadWorkspaceName(ticketId) {                 // async function ВСЕГДА возвращает Promise
  try {
    const ticket = await getTicketAsync(ticketId);            // await "разворачивает" Promise, приостанавливая функцию (не поток!)
    const user = await getAssigneeAsync(ticket.assigneeId);
    const workspace = await getWorkspaceAsync(user.workspaceId);
    return workspace.name;
  } catch (error) {                                            // try/catch ловит и синхронные ошибки, и отклонённые Promise
    console.error('где-то в цепочке:', error.message);
    throw error;                                                 // важно: проброс, иначе вызывающий код не узнает об ошибке
  }
}
loadWorkspaceName(1).then(name => console.log(name));           // async-функцию вызывают как обычный Promise
🔬 Под капотом: await не блокирует поток — что именно "приостанавливается"

await не останавливает браузер/Node — он останавливает выполнение ТОЛЬКО текущей async-функции, возвращая управление в event loop; остальной код (другие обработчики событий, таймеры) продолжает выполняться нормально. Технически каждый await — это точка, где функция «разбивается» на продолжение (continuation), которое ставится в microtask-очередь, когда Promise разрешится. Именно поэтому async/await совместим с однопоточной моделью из раздела 9 — под капотом это всё те же microtasks.

11.2 AbortController — отмена запроса

function loadWithTimeout(url, ms = 3000) {
  const controller = new AbortController();
  const timer = setTimeout(() => controller.abort(), ms);      // если за ms не успели — отменяем сами

  return fetch(url, { signal: controller.signal })               // signal связывает fetch с контроллером
    .finally(() => clearTimeout(timer));                          // не забыть снять таймер при успехе
}

// отмена при повторном поиске (частый паттерн: пользователь печатает быстрее, чем отвечает сервер)
let currentController = null;
async function search(query) {
  currentController?.abort();                    // отменяем ПРЕДЫДУЩИЙ незавершённый запрос
  currentController = new AbortController();
  try {
    const res = await fetch(`/api/search?q=${query}`, { signal: currentController.signal });
    return res.json();
  } catch (error) {
    if (error.name === 'AbortError') return null;    // отмена — это тоже "ошибка" с точки зрения fetch, но ожидаемая
    throw error;
  }
}

11.3 Таймеры, debounce и throttle своими руками

Оба паттерна ограничивают частоту вызова функции, но по-разному:

DebounceThrottle
Идея«подожди тишины» — выполнить только после паузы«не чаще, чем раз в N мс» — регулярный ритм
Примерпоиск по вводу текста — ждём, пока пользователь перестанет печататьобработчик скролла/resize — не считать координаты 60 раз в секунду
Сколько вызовов при непрерывном потоке событийодин — в самом концерегулярно, через равные интервалы
function debounce(fn, delay) {
  let timer = null;
  return (...args) => {
    clearTimeout(timer);                          // каждый новый вызов ОТМЕНЯЕТ предыдущий отложенный
    timer = setTimeout(() => fn(...args), delay);
  };
}

function throttle(fn, interval) {
  let lastCall = 0;
  return (...args) => {
    const now = Date.now();
    if (now - lastCall >= interval) {              // пропускаем вызов, только если прошло достаточно времени
      lastCall = now;
      fn(...args);
    }
  };
}

Оба реализуются в сессии 5 с тестами через node --test и поддельные таймеры — здесь только принцип. Обратите внимание: обе функции — сами по себе пример замыкания из раздела 6 (timer и lastCall живут между вызовами возвращённой функции).

🔬 Под капотом: capturing vs bubbling: третий аргумент addEventListener

Событие сначала идёт ВНИЗ от document к цели (capturing phase), затем «отскакивает» и идёт ВВЕРХ от цели обратно к document (bubbling phase). По умолчанию addEventListener(type, fn) слушает фазу всплытия (bubbling) — поэтому делегирование работает: клик по дочернему элементу «всплывает» до родителя с обработчиком. Третий аргумент { capture: true } заставит слушать фазу погружения — редко нужно, но объясняет, почему event.stopPropagation() в обработчике на дочернем элементе может помешать родительскому обработчику сработать вообще.

14.3 Собственная реактивность: Proxy + подписчики

То, что Vue называет reactive(), — не магия, а объект Proxy, перехватывающий чтение и запись полей, плюс список функций-подписчиков, которые перезапускаются при изменении. Полная реализация — в сессии 7; здесь принцип на 20 строках.

function reactive(target, onChange) {
  return new Proxy(target, {
    get(obj, key) {
      return obj[key];                                       // здесь МОГЛА бы быть регистрация "кто читает" — полная версия в сессии 7
    },
    set(obj, key, value) {
      const old = obj[key];
      obj[key] = value;
      if (old !== value) onChange(key, value, old);          // уведомляем подписчиков ТОЛЬКО если значение реально изменилось
      return true;                                             // обязательный return true — иначе Proxy кидает TypeError в strict mode
    },
  });
}

const state = reactive({ count: 0 }, (key, value) => {
  console.log(`state.${key} изменилось на`, value);
  render();                                                     // "рендер" — просто функция, перерисовывающая DOM
});

state.count++;              // console: "state.count изменилось на 1"; render() вызван автоматически
🔬 Под капотом: чего не хватает этой мини-версии до настоящего Vue reactive()

Три вещи: (1) автоматическое отслеживание зависимостей — Vue не требует явно писать onChange, он сам запоминает, какие реактивные поля были прочитаны ВНУТРИ конкретной функции-эффекта (через ловушку get), и перезапускает только те эффекты, что зависят от изменившегося поля; (2) глубокая реактивность — вложенные объекты тоже должны стать Proxy при первом чтении (лениво, а не сразу рекурсивно); (3) батчинг обновлений — несколько синхронных изменений должны вызвать один перерендер, а не N. Все три — то, что вы реализуете пошагово в сессии 7, дойдя до узнаваемого мини-ref()/reactive().

Шаг 3.2Каррирование и мемоизация: измеримая разница до/после#

Каррирование и мемоизация не как абстрактные примеры из книжки, а с измеримым эффектом: секундомер до/после мемоизации.

// ── мемоизация с измерением времени ──────────────────────────────────────────
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}

function slowFibonacci(n) {                        // намеренно неэффективная рекурсия — экспоненциальное время
  if (n <= 1) return n;
  return slowFibonacci(n - 1) + slowFibonacci(n - 2);
}
const fastFibonacci = memoize(slowFibonacci);        // ЗАМЕТЬТЕ: мемоизирует только внешний вызов, не рекурсивные — см. "под капотом"

Шаг 5.3debounce/throttle с тестами на встроенном node --test + mock.timers#

// src/async/timing.js
export function debounce(fn, delay) {
  let timer = null;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}

export function throttle(fn, interval) {
  let lastCall = 0;
  let timeoutId = null;
  return (...args) => {
    const now = Date.now();
    const remaining = interval - (now - lastCall);
    if (remaining <= 0) {
      clearTimeout(timeoutId);
      lastCall = now;
      fn(...args);
    } else if (!timeoutId) {                          // догоняющий вызов в конце паузы — иначе последнее событие потеряется
      timeoutId = setTimeout(() => { lastCall = Date.now(); timeoutId = null; fn(...args); }, remaining);
    }
  };
}

Шаг 7.3Своя reactive()/effect(): автотрекинг зависимостей + батчинг через microtask#

Главное блюдо лабы: полноценная мини-версия reactive()/ref() — с автоматическим отслеживанием зависимостей (не вручную указанным onChange, как в разделе 14) и батчингом обновлений.

// src/web/app/reactive.js

let activeEffect = null;                                  // "какой эффект сейчас выполняется" — глобальная точка привязки

export function effect(fn) {
  const wrapped = () => { activeEffect = wrapped; fn(); activeEffect = null; };
  wrapped.deps = new Set();                                   // на какие поля подписан этот эффект (для будущей отписки)
  wrapped();                                                    // выполнить сразу — заодно СОБРАТЬ зависимости при первом чтении
  return wrapped;
}

const targetMap = new WeakMap();                            // target → (key → Set<effect>) — WeakMap из раздела 8: объект удалён → карта тоже очистится

function track(target, key) {
  if (!activeEffect) return;                                    // чтение вне effect() — трекать некого
  let depsMap = targetMap.get(target);
  if (!depsMap) targetMap.set(target, depsMap = new Map());
  let dep = depsMap.get(key);
  if (!dep) depsMap.set(key, dep = new Set());
  dep.add(activeEffect);
  activeEffect.deps.add(dep);
}

// ── батчинг: несколько синхронных изменений → ОДИН перезапуск эффекта ────────
const pendingEffects = new Set();
let isFlushing = false;

function trigger(target, key) {
  const dep = targetMap.get(target)?.get(key);
  if (!dep) return;
  dep.forEach(fn => pendingEffects.add(fn));
  if (!isFlushing) {
    isFlushing = true;
    queueMicrotask(() => {                                       // microtask (раздел 9!) — все синхронные изменения этого "тика" уже накопились
      pendingEffects.forEach(fn => fn());
      pendingEffects.clear();
      isFlushing = false;
    });
  }
}

export function reactive(target) {
  return new Proxy(target, {
    get(obj, key, receiver) {
      track(obj, key);
      const value = Reflect.get(obj, key, receiver);
      return typeof value === 'object' && value !== null ? reactive(value) : value;   // ЛЕНИВАЯ глубокая реактивность
    },
    set(obj, key, value, receiver) {
      const old = obj[key];
      const result = Reflect.set(obj, key, value, receiver);
      if (old !== value) trigger(obj, key);
      return result;
    },
  });
}

Шаг 8.1Свой роутер: history.pushState, параметры пути, popstate#

Свой роутер на History API — без перезагрузки страницы, без хэшей в URL. Перехватываем клики по ссылкам, слушаем кнопки «назад/вперёд».

// src/web/app/router.js

const routes = [];                                          // [{ pattern: RegExp, params: [names], handler }]

export function route(path, handler) {
  const paramNames = [];
  const pattern = new RegExp('^' + path.replace(/:(\w+)/g, (_, name) => {
    paramNames.push(name);
    return '([^/]+)';                                        // :id → захватывающая группа "всё, кроме /"
  }) + '$');
  routes.push({ pattern, paramNames, handler });
}

function resolve(pathname) {
  for (const { pattern, paramNames, handler } of routes) {
    const match = pathname.match(pattern);
    if (match) {
      const params = Object.fromEntries(paramNames.map((name, i) => [name, match[i + 1]]));
      return { handler, params };
    }
  }
  return null;
}

function handleLocation() {
  const found = resolve(location.pathname);
  if (found) found.handler(found.params);
  else console.warn('404: нет маршрута для', location.pathname);
}

export function navigate(path) {
  history.pushState(null, '', path);                          // меняет URL, БЕЗ перезагрузки страницы
  handleLocation();                                             // но роутер сам не узнает об этом — вызываем вручную
}

  document.addEventListener('click', (event) => {               // делегирование КЛИКОВ ПО ССЫЛКАМ на уровне всего документа
    const link = event.target.closest('a[data-link]');           // только ссылки, помеченные data-link — обычные <a> ведут себя как обычно
    if (!link) return;
    event.preventDefault();                                       // не даём браузеру делать полную перезагрузку
    navigate(link.getAttribute('href'));
  });
  window.addEventListener('popstate', handleLocation);           // кнопки браузера "назад"/"вперёд"
  handleLocation();                                                // первая загрузка — обработать текущий URL
}
Зачем: history.pushState меняет адресную строку и добавляет запись в историю браузера, но НЕ вызывает никаких событий и не перезагружает страницу — поэтому navigate() обязан сам вызвать handleLocation() сразу после. А вот кнопки «назад»/«вперёд» браузера как раз генерируют событие popstate — на них подписка обязательна, иначе URL поменяется, а контент останется прежним. event.preventDefault() в обработчике клика — без него браузер выполнил бы обычный переход по ссылке с полной перезагрузкой, обнуляя весь JS-стейт (ровно то, чего SPA избегает).

  error: null,

export async function loadTickets() {
  store.loading = true; store.error = null;
  try { store.tickets = await fetchTickets(); }
  catch (e) { store.error = e.message; }
  finally { store.loading = false; }
}

export async function changeStatus(id, status) {
  const before = store.tickets.find(t => String(t.id) === String(id))?.status;
  const ticket = store.tickets.find(t => String(t.id) === String(id));
  if (ticket) ticket.status = status;                        // оптимистично: reactive() САМА уведомит подписанные effect()
  try { await updateTicketStatus(id, status); }
  catch (e) { if (ticket) ticket.status = before; store.error = `Не удалось сохранить: ${e.message}`; }   // откат при ошибке
}

18. Глоссарий #

Hoisting — поднятие объявлений переменных и функций в начало области видимости на этапе, предшествующем выполнению.
TDZ (Temporal Dead Zone) — промежуток между началом блока и объявлением let/const, где переменная зарегистрирована, но недоступна.
Function scope / block scope — область видимости, ограниченная функцией (var) или блоком { } (let/const).
Coercion (приведение типов) — автоматическое преобразование значения к другому типу при операции (например, в ==).
Truthy / falsy — какое булево значение получит значение при неявном приведении к boolean; ложны ровно 8 значений.
this — ссылка на контекст вызова функции; определяется способом вызова, кроме стрелочных функций (лексический this).
call / apply / bind — явное управление this: call/apply — вызов с заданным this, bind — новая функция с намертво зафиксированным this.
Замыкание (closure) — функция, сохраняющая доступ к переменным области, где была создана, даже после завершения этой области.
Каррирование — преобразование функции от нескольких аргументов в цепочку функций от одного аргумента.
Мемоизация — кэширование результата функции по аргументам вызова.
Module pattern — приватность через замыкание — единственный способ инкапсуляции в JS до появления #private.
Прототип — объект, к которому обращается движок при поиске отсутствующего у объекта поля.
Object.create(proto) — создать объект с явно заданным прототипом, без class и new.
class — синтаксический сахар над прототипным наследованием; сам является функцией.
#private field — приватное поле класса, недоступное вне тела класса на уровне синтаксиса (не соглашения).
static — поле или метод, принадлежащий классу целиком, а не отдельному экземпляру.
Symbol — примитив, гарантированно уникальное значение; используется как «незасоряющий» ключ объекта.
Map / Set — структуры данных: Map — ключ-значение с любым типом ключа; Set — уникальные значения.
WeakMap / WeakSet — версии Map/Set со слабыми ссылками на ключи — не мешают сборщику мусора, не перечисляемы.
Call stack — стек вызовов — что выполняется прямо сейчас, синхронно.
Microtask queue — очередь высокого приоритета (Promise.then, queueMicrotask); опустошается целиком перед каждым macrotask.
Macrotask queue — очередь низкого приоритета (setTimeout, I/O, события); обрабатывается по одной задаче за раз.
Promise — объект будущего значения с тремя состояниями: pending, fulfilled, rejected.
async/await — синтаксический сахар над Promise; await приостанавливает функцию, не поток.
AbortController — механизм отмены fetch и других отменяемых операций через AbortSignal.
Debounce / throttle — ограничение частоты вызова функции: «подождать тишины» vs «не чаще раза в N мс».
Event delegation (делегирование) — один обработчик на родителе вместо многих на потомках, использующий всплытие события.
ESM (ES Modules) — стандартный синтаксис import/export, статически резолвимый, работающий в браузере без сборки.
CommonJS — модульная система Node.js (require/module.exports), динамически резолвимая.
localStorage / sessionStorage — браузерное хранилище строк: постоянное / на время вкладки.
structuredClone — встроенная функция глубокого клонирования, сохраняющая Date, Map, Set, циклические ссылки.
Proxy — объект-перехватчик операций (чтение/запись/удаление) над другим объектом.
Reactive / effect (собственная реализация) — Proxy-based система: чтение регистрирует зависимость, запись вызывает подписанные эффекты.
Автотрекинг зависимостей — автоматическое определение, какие поля читает эффект, без явной подписки.
Батчинг — объединение нескольких синхронных изменений в один перезапуск эффекта через microtask.
history.pushState / popstate — API для смены URL без перезагрузки страницы / событие кнопок навигации браузера.
node:test — встроенный в Node.js тестовый раннер, без внешних зависимостей (аналог Vitest/Jest).
